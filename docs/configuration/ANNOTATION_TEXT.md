# Annotation text across GuicedEE modules

GuicedEE-owned configuration annotations use the shared `Environment` resolver when
their text reaches a runtime setting. The audit inventories **266 text members in 69
annotations across 31 runtime modules**, including modules with no owned text members.
See the [member inventory](module-annotation-text.json) and its
[reviewed declarations](module-annotation-text-reviewed.json).

For `@MailConnectionOptions(value = "orders", hostname = "MAIL_HOST_SETTING")`:

1. Check `MAIL_ORDERS_HOSTNAME` across all configured sources.
2. Check `MAIL_HOSTNAME` across all configured sources.
3. Look up the annotation text `MAIL_HOST_SETTING` across those sources.
4. If absent, retain `MAIL_HOST_SETTING` literally.

Every key uses JVM properties, OS environment, `.env.local`, `.env`, then registered
application defaults. OS and dot-env keys support the exact name and uppercase form
with dots/hyphens replaced by underscores. Scoped keys precede global keys even when
the scoped value comes from a file and the global value comes from a JVM property.
An explicit empty value stops lookup; each option's documented empty/inherit semantics
then apply. Scope selectors use the annotation's declared name, while connection and
consumer registries use the effective resolved name.

`${NAME}`, `${NAME:default}`, `${NAME:-default}` and nested placeholders remain supported.
String arrays resolve each entry before module-specific joining/splitting. Bare names
are followed once: referenced values can contain placeholders, but are not repeatedly
treated as more bare names. Explicit normal-key overrides remain values, even if their
text happens to match another property. REST clients resolve configuration before URL
routing, authentication headers and TLS options; those consumers do not resolve it again.

The audit corrected Consul and service-discovery readers that bypassed dot-env files,
Hazelcast fallbacks, scoped empty values, CORS/RabbitMQ arrays, messaging registration
names, REST client repeated resolution, service-registration metadata, logger names,
and persistence package names. Cloud platform annotation defaults now feed their
providers and metadata; normal platform variables still win. An annotation alone does
not satisfy deployment detection. Provider metadata such as Lambda handler, instance
size and cluster name describes the deployment; it does not configure cloud resources.

`@EnvironmentProperty.name` is a literal configuration key identifier. The built-in
logger injector consumes `@InjectLogger.value`; `level`, `fileName` and
`rollingFileName` remain reserved hints with no built-in setting to apply. Standard
and third-party annotation contracts, including Guice/Jakarta `@Named` qualifiers and
Jakarta REST paths, retain their defined semantics. Java reflection exposes declarations;
resolution happens at GuicedEE's configuration consumers.

## Validation and maintenance

The focused reactor passed **113 tests** across 19 packaged modules. The isolated
module probe passed **301 assertions** covering text getters, scoped source order, empty overrides, arrays,
registration maps, service metadata, platform providers and request-header consumption.
It does not require Kafka, RabbitMQ, IBM MQ, SMTP, Consul, a database or a live cloud.
The six SPI/scanner discovery probes and seven benchmark smoke cases also passed.
Website compilation and both generated-inventory drift checks passed.

```powershell
python GuicedEE/website/tools/module_annotation_text.py
python GuicedEE/website/tools/module_annotation_text.py --check
python benchmarks/tools/module-annotation-contract/verify.py
```

The module probe requires fresh module classes and each module's
`target/annotation-text-classpath.txt`, generated by Maven `dependency:build-classpath`
with `-Dmdep.outputFile=target/annotation-text-classpath.txt -DincludeScope=test`.
The generator fails if declarations differ from the reviewed member set. This inventory
guards coverage changes; executable checks verify behavior. Local compilation and probes
do not establish publication, website deployment or live broker/database/cloud operation.
